## The epic's signature defect: the guard that proves nothing

Epic 1's retrospective named this family. Epic 3 met it **eight more times**, and — the part worth
sitting with — **three of those were introduced by me while fixing something else.**

| Where | The guard | Why it proved nothing |
| --- | --- | --- |
| 3.4 | SQL-leak test | `JSON.stringify` escapes newlines, so the raw SQL was never a substring of the response |
| 3.5 | Leading-dot regex test | Passed identically with and without the fix |
| 3.6b | `attempts: 1` | Changing it to 3 failed no test |
| 3.6b | AC4 session persistence | Never implemented; no test asked |
| 3.6b | AC7 target size | Never implemented; no test asked |
| 3.7 | `does not log` | Covered one of the two branches; deleting the other left 53 green |
| 3.8 | `no column named sqlText` | A column by that name was never possible |
| 3.8 | AC1 per-row SQL | In the export only; the criterion says per row |

**The pattern underneath:** a test written *while fixing something else* gets the least scrutiny and
deserves the most. Story 3.8's vacuous test was written one commit before the MR opened, in the same
edit that added a feature. Story 3.6b's two unimplemented ACs survived four green review rounds.

**What actually catches this** is the sensitivity check — break the covered code, confirm the test
fails, restore. It was run on every story in this epic and caught every one of the mutations it was
pointed at. What it cannot catch is a criterion with no test at all, which is what the AC audit is
for.

## The practice that earned its place: the AC audit before the MR

Reading the acceptance criteria one clause at a time against the code, **before** opening the merge
request.

| Story | What the audit found |
| --- | --- |
| 3.6b | AC4 and AC7 unimplemented — *found after the MR merged*, requiring a follow-up chore MR (!47) |
| 3.6c | Nothing. All seven met. |
| 3.7 | Nothing. All eight met. |
| 3.8 | AC1's per-row SQL clause unmet — found **before** the MR, fixed in the same branch |

Both hits were clauses **partly** satisfied. That is the shape reviewers are structurally worst at
seeing: the code in front of them looks finished, and only the criterion knows what is missing.
Reviewers check the code that exists; only the AC list checks for code that is absent.

The audit moved from after the reviews (3.6b) to before the MR (3.7, 3.8). That ordering is the
lesson — on 3.8 it caught AC1 in time to ship in the same branch instead of a follow-up MR.

## Review economics

| Story | Argus rounds | CLI findings | MR rounds to clean |
| --- | --- | --- | --- |
| 3.1 | whole-story | 13 (10 applied) | 3 |
| 3.2 | 5 | 13 (all applied) | 4 |
| 3.3 | 4 | 6 (all applied) | 4 |
| 3.4 | 3 | 8 | 2 |
| 3.5 | 3 | 1 round | 4 |
| 3.6a | — | 6 | 3 |
| 3.6b | 2 | 6 | 1 + a follow-up chore MR |
| 3.6c | 2 | **0** | 1 (clean first pass) |
| 3.7 | 3 | **0** | 0 (no MR review ran — see below) |
| 3.8 | 5 | 6 (5 applied) | 2 |

**The trend is real and it is downward.** Stories 3.1–3.3 took 3–4 MR rounds each; 3.6c was reviewed
clean on the first pass and 3.7's CLI round found nothing. The first two clean CLI rounds this project
has ever had were both in the second half of this epic.

**What changed:** the local Argus round moved before the CLI round, the CLI round moved before the MR,
and the AC audit moved before the MR. Each shift moves a finding earlier, where it costs a commit
instead of a review cycle.

**Argus's false-positive rate is worth naming.** It raised at least five findings this epic that were
wrong on inspection — a `RangeError` that does not occur, a "flaky" test whose id is `uuidv7()` and
therefore chronological, a `resetAllMocks` claim contradicted by a two-minute probe, `next/link`
"requiring JavaScript", and a token leak the code already prevents. **Every rejection was settled by
a probe, not an argument**, and two of them exposed real gaps anyway: the token leak was unenforced
(now tested), and the `resetAllMocks` reasoning now lives in the code so it is not re-raised.

## What went badly

**A bug landed four times and was invisible every time.** A `\b` written through a shell heredoc
arrives in the file as a literal backspace byte — a command string loses one level of backslash
escaping before the shell sees it. It went into a regex on 3.5 (compiled fine, matched nothing), then
into the *paragraph explaining that failure* on 3.8, twice. `docs/no-control-characters.test.ts` now
reads the bytes, and found a fourth instance sitting in story 3.5's record since the day it shipped.
The rule now is: anything carrying a backslash goes through the editing tool, never a heredoc.

**One CSV defence was bypassed twice, by two different reviewers.** First a leading space
(`" =cmd|…"` — the check read `charAt(0)`), then a full-width `＝`. Two independent rounds beating on
the same control is a fair argument for treating "neutralise formulas" as something to keep attacking
rather than a box to tick.

**Story 3.6 was mis-sized and had to be split mid-epic** into 3.6a/b/c. As written it meant a Python
HTTP server, a Node client, and three UX requirements. The split was the right call and the record
says so; the lesson is that "a surface plus the wire it needs" is two stories.

**Story 3.7 merged with no MR-level review.** The only service-account note on !49 is a rate-limit
notice. The code is not unreviewed — three Argus rounds and a clean CLI round over 9 of 9 files ran on
that exact SHA — but the second look did not happen, and the record says so rather than implying it
did.

**False-clean states keep appearing in new places.** A rate-limit notice looks like a review. A
skipped `test:db` suite looks like "no database here" when it is really "no env file". A summary note
edited in place becomes a review hours later. Each was caught, but only by checking the specific
evidence — the embedded commit range, the actual skip reason — rather than the surface signal.

**I reported `test:db` as unrunnable when it was not.** I invoked `vitest` directly instead of through
`npm run test:db`, which loads `.env.local`. The project lead corrected it, and the grant behind AD-12
went from asserted to proven (`42501 permission denied` when pointed at the reader role). The general
form: *a skip for want of configuration and a skip for want of capability are indistinguishable from
the outside.*

## What went well

- **AD-7's validator exists and is load-bearing.** The product's central claim — no figure reaches a
  board member that is not in the rows beneath it — is enforced by code, tested against planted
  hallucinations, and now has an honest surface when it refuses.
- **The three failure states are genuinely distinct**, and each test asserts the *absence* of the
  other two, so one lump cannot pass three tests.
- **No client JavaScript where none was needed.** The ask field and the access-log filters are plain
  GET forms; `required` + `pattern` does AC5's work with JS disabled. UX-DR7's "no intermediate empty
  state" is satisfied by construction rather than by care.
- **Capability separation held under pressure.** The access log's reader is a separate port on the
  writer credential, because the write port's own comment said a `find` there would hand the audit
  trail to its own subject. The rule was written in Epic 3's first story and obeyed in its last.
- **The gate caught what the suite could not, repeatedly.** `tsc` found two type errors that 54
  passing tests ran straight past; the docs suite has caught a planning-only change breaking `main`
  before.

## Next epic: Epic 4 — The Watchdog

Eight stories. The system flags probable duplicates, unusual vendor billing and missed dues **without
being asked**, and every finding lands in a permanent register.

**It does not depend on Epic 3.** The epics document says so explicitly ("Does not require Epic 3"),
and that is worth stating plainly: Epic 3 built a question-answering path, Epic 4 builds proactive
detection over the same Epic 1 data. The shared surface is the dashboard.

**What Epic 3 hands it:**

- The provenance pattern (AD-12) and the access-log reader as a worked example of the read/write port
  split
- `docs/no-control-characters.test.ts`, now part of the gate
- The design-token surface pattern: props-driven components, tokens not literals, 24×24 targets, the
  global focus ring
- The AC-audit-before-MR practice, which is the single highest-yield process change this epic made

**What to watch:**

- Epic 4's standalone claim is conditioned: *"provided detection and alert copy are deterministic
  rather than model-generated."* That open question should be settled before 4.1, not during it.
- 4.8 sends email with "no model in the loop" — an outbound side effect, the first in the product.
- 4.5–4.7 are three surface stories in a row. Epic 3's evidence says surface stories are where
  partly-satisfied criteria hide, so the AC audit matters most there.

## Team agreements carried into Epic 4

1. **The AC audit runs before the MR is opened**, not after the reviews. On 3.8 that difference was a
   fix in the same branch versus a follow-up MR.
2. **Every review fix gets the sensitivity check**, because a fix is the highest-risk diff in a story,
   not the lowest. Three of this epic's vacuous guards were introduced while fixing something else.
3. **Reject a review finding only with a probe**, never with an argument. Five Argus findings were
   rejected this epic; each rejection ran code first, and two of them exposed real gaps anyway.
4. **Anything carrying a backslash is written with the editing tool**, never through a shell heredoc.
5. **Distinguish "clean" from "did not run."** A rate limit, a skipped suite, a paused reviewer and a
   genuine pass all look alike from outside. Check the embedded commit range and the actual skip
   reason.
6. **An action item that is not wired into a gate, a script or a skill file will not be done.** One of
   Epic 1's eight was completed, and it was the one written into a file the next run reads.
