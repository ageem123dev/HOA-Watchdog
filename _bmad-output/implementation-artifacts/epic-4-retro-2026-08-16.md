## The practice that paid for itself: the AC audit

Epic 3's retrospective made one process change — *"the AC audit runs before the MR is opened, not
after the reviews"* — and it is the clearest evidence this project has that **a mechanism beats an
intention**.

It has now found something on **nine consecutive stories**. In Epic 4 alone:

- **4.1** found something the review rounds did not
- **4.6** found `period` read by the adapter, carried by the port and the view, and rendered by
  nothing
- **4.7** found the page and its export reading a repeated URL parameter two different ways
- **4.8** found **three** gaps, one of which was an acceptance criterion that had not been
  implemented at all — AC10 asked for a structural assertion that no model sits in the alerting
  path, and nothing did that. Epic 4's independence from Epic 3 was resting on a sentence in a
  planning document.

Nine for nine. Whatever else this retrospective says, that practice stays.

## The epic's signature defect: the vacuous guard, again

Epic 3's signature defect was *"the guard that proves nothing."* Epic 4 met it again, in every
story that had surface or query logic — 4.1, 4.3, 4.5, 4.6 and 4.8 all record at least one.

**Story 4.8 alone shipped five tests that proved nothing**, and the distribution of *who caught
them* is the finding:

| Caught by | Count | What it was |
| --- | --- | --- |
| My own sensitivity check | 1 | A surrogate-splitting test whose cap landed on an even boundary, so the cut never straddled a pair |
| My own sensitivity check, on a **fix** | 2 | A dead `Symbol` branch whose removal changed nothing; a guard list whose entries could be deleted without failing anything |
| **CodeRabbit, MR round 1** | 4 | An ordering assertion comparing two identical queries; `toContain('12')` against a fixture containing `1240.00`; a wiring test restating its predecessor; an accounting decision never pinned |

**The test-value pass ran on every task of that story and caught none of the four.** That is not a
diligence problem — it is a scope problem. The pass as written asks *"break the code this test
covers; does it fail?"*, and I applied it to the production mutations I judged load-bearing. The
four that escaped were cases where the **fixture** made the assertion vacuous, not the production
code: an amount containing the substring being asserted, two reads of an unchanged table, an
assertion restating its neighbour. Mutating production code cannot surface any of those.

**This is the third epic in which this class has appeared.** It is not going away by being written
down again.

## What went well

- **Detection is genuinely deterministic, and provably so.** The open question Epic 3's retro said
  must be settled before 4.1 *was* settled before 4.1 — and by 4.8 it was a test rather than a
  decision.
- **Epic 4 stood alone, as designed.** It never touched Epic 3's agent path. The epics document
  claimed the two were swappable; that claim survived contact.
- **The review gate on fix diffs kept earning its place.** Story 4.8's `.catch(() => '')` — which
  would have recorded a connection reset mid-body as a successful delivery and never retried it —
  was introduced *while fixing* the empty-body defect and caught by the gate on the fix diff. Two of
  that story's defects came from fixes rather than first-draft code.
- **Rejections were probed, not argued.** Every declined finding this epic ran code first: Node 24's
  redirect behaviour was measured against two local servers, `AbortSignal.timeout`'s unref was
  measured, `tabular.ts` was read to disprove the empty-`records` claim. Two of those probes changed
  the fix even though they refuted the stated reason.
- **The close-out rode in the round's commit.** Story 4.8 merged *while the final gates were
  running*, and `main` still carried the correct status. Five earlier stories needed follow-up docs
  MRs for exactly that race; this epic needed none.

## What went badly

**1. Epic 3's highest-consequence action item was not done, for the second epic running.**
`migrations/roles.test.ts` still executes `update board_member set display_name = 'changed'` and
`delete from board_member` with no `WHERE`, to prove the reader role cannot write. On the one run
where that grant has regressed, the test is the thing that rewrites or empties the table it exists
to protect. The fix is known and was applied to the identical shape in `query-log.test.ts` in Epic
3. It has now survived two retrospectives as a bullet point.

**2. `.gitattributes` looks done and is not.** The file exists, dated during Epic 3, and covers
`samples/*` binaries. It contains **no `* text=auto`**, so every source file still shows `i/lf
w/crlf attr/` — the index is LF, the working tree is CRLF, and nothing declares it. Every commit
this epic emitted CRLF warnings.

That is not cosmetic. It cost real time in Epic 4: scripted edits repeatedly failed to match their
anchors because the pattern used `\n` and the file used `\r\n`, and on story 4.8 one such failure
**silently did not apply** — and I then reported the file as fixed on a review thread. It took
CodeRabbit's round-2 re-review to surface that `.env.example` was still carrying the wrong sentence
a full round later.

**3. I made a claim that was not true, and the mechanism to prevent it already existed.** The rule
*"a replacement not proven to have landed is not a change"* is written down from an earlier epic. It
failed here because an assertion error was read as belonging to the next statement rather than the
one that raised it. The fix is not "be more careful": it is to read the file back after any scripted
edit, which is what was done for the remainder of the story.

**4. Control characters reached source twice more.** Stories 4.7 and 4.8 both hit it, and 4.8 hit it
three times in a row while writing the very fixtures that test for it — a string argument carrying
an escape sequence arrives as the real byte. The open action item to widen
`docs/no-control-characters.test.ts` beyond markdown was raised in 4.6 and is still open. It would
have caught none of these (they were deliberate fixtures) but the underlying hazard is now
demonstrated four times across three epics.

**5. The product still has not been run by anyone.** Epic 3's retrospective closed with *"Epic 3 is
complete and entirely unexercised: never deployed, no board member has seen it."* That is now true
of Epic 3 **and** Epic 4. Every claim of correctness in this epic is about tests and reviews, not
about a treasurer receiving an alert.

## Significant discovery: the pilot is built and unexercised

This is the finding that should shape whatever comes next.

Epics 1 through 4 are complete. The system can take a document, read it, store the records, answer a
question about them with provenance, detect three classes of anomaly, and email the board about one
— and **not one line of it has been run by a board member.** There is no deployment, no association
onboarded, and the catalog holds a single entry.

Every quality claim in four retrospectives is a claim about tests and reviews. That is a real form of
evidence and this project has been unusually rigorous about it. It is not the same as evidence that
the product works, and the gap widens with each epic that ships without contact.

Epic 5 adds a *new intake channel* to a product whose existing intake channel has never been used in
anger. That ordering is worth questioning explicitly before it is planned.

## Agreements carried forward

The four that held are kept unchanged:

1. **The AC audit runs before the MR is opened.** Nine consecutive stories.
2. **Every review fix gets the sensitivity check.** Two of Epic 4's worst defects were introduced by
   fixes.
3. **Reject a review finding only with a probe, never with an argument.**
4. **Distinguish "clean" from "did not run."** A rate limit, a paused reviewer and a genuine pass
   look identical from outside.

Two are revised because they failed as written:

5. **~~Anything carrying a backslash goes through the editing tool~~** → **Any scripted edit is read
   back afterwards.** The original rule was correct and got broken anyway; the replacement does not
   depend on remembering it at the moment of writing, only at the moment of finishing. It is the
   only thing that would have caught the `.env.example` claim.
6. **An action item that is not wired into a gate, a script or a skill file will not be done.**
   Unchanged, and this retrospective is its second confirmation. Items 1–5 above are all one-file
   changes for exactly this reason.
