- (event by facilitator) Run started. Mode: Coaching path. Stakes: REGULATED — board members carry fiduciary liability and the UI is the evidence surface for that diligence. Accessibility is a floor requirement, not an enhancement; language gets review; every place the interface could mislead a board member into a wrong financial decision is in scope.
- (decision by facilitator) Sources confirmed: docs/prd/prd.md, ARCHITECTURE-SPINE.md (final, 15 ADs), and the architecture run's .memlog.md. All three already read in this session — no extraction subagent needed.
- (override by facilitator) EXPLICITLY OUT OF SCOPE as a design input: the three HTML renderings produced during the architecture run (board-explainer, security-posture, architecture-walkthrough). Their ledger-paper palette, monospace display type and oxide-red accents were the facilitator's choices for internal documents. Carrying them into the product UI would impose an unelicited direction. They become an input only if the user explicitly picks them.
- (decision by user) FRONT DOOR = the dashboard, status-first. Cash position, alerts and what-needs-attention on landing; the Oracle is a panel or page opened from there. Passive anomaly detection (FR-6/FR-7) therefore has a permanent home surface rather than depending on the user thinking to ask. Accepted cost: one extra step in the UJ-2 live-meeting moment, which the Oracle's entry point must then make fast.
- (decision by user) FORM FACTOR = responsive web, desktop-primary. Built for laptop; usable on a phone chiefly so a board member can open a finding from an alert email on the device in hand. Consequence to design deliberately: the FR-5 evidence tables do not collapse gracefully and need a real narrow-viewport treatment, not a horizontal scroll.
- (decision by user) EVIDENCE DENSITY: an Oracle answer always shows the prose answer AND the data table it came from. The exact SQL sits behind a disclosure, one interaction away. Evidence is present by default rather than on demand — the treasurer never has to know to ask for it. Realizes FR-5 and makes AD-7's guarantee visible.
- (decision by user) ALERT LIFECYCLE: alerts CANNOT be dismissed by opinion. They resolve only when the underlying condition changes, or they age. Strongest possible fiduciary record — nothing disappears because someone disagreed with it. Cost accepted: the dashboard must stay usable while carrying alerts the board cannot clear.
- (assumption by facilitator) OPEN CONSEQUENCE: under AD-1 (uploads-only, no bank feed) several alert types have NO natural resolution event. A duplicate-invoice flag that the board correctly acted on by NOT paying it has nothing to detect — there is no payment feed to observe the non-payment. Without dismissal, such an alert would persist indefinitely on the dashboard. 'Resolve' therefore needs an explicit definition per finding type before IA can close.
- (decision by user) ALERT RESOLUTION = two-tier. Nothing is ever closed or deleted. Reviewed alerts move from the active dashboard into a permanent REVIEWED REGISTER that stays searchable and exportable; the dashboard shows only what nobody has looked at yet. Resolves the no-natural-resolution problem without reintroducing dismissal-by-opinion, and the register directly serves UJ-1's 'export the finding for the next board packet'. New IA surface implied: the register.
- (decision by user) NFR-5 GETS A SURFACE: an access log the board can read — who asked what, when, searchable and exportable. Turns the diligence claim from assertion into something demonstrable, and answers the question a resident or director will eventually raise: who has been looking at member financial data? IA closes at 8 surfaces: Dashboard, Oracle, Upload, Alert detail, Reviewed register, Quarantine queue, Access log, Sign-in.
- (decision by user) VISUAL DIRECTION = A · INSTITUTIONAL. Serif figures, hard rules, navy/stone/brass. Status encoded as a margin tick rather than a colored pill. Reads as produced by an institution rather than an app. Palette from the rendered direction: ink #14213D, stone #E5E5E0, brass #A47E3B, flag #8C2F1E. Artifact: .working/directions-4.html
- (assumption by facilitator) RISK carried by direction A, flagged at pick time and accepted: formality can read as austere to a non-finance volunteer. Primary mitigation available is microcopy register — formal structure paired with plain language. Being elicited next, not assumed.
- (decision by facilitator) Direction A absorbs the no-dismissal alert model well: a register of findings is expected to accumulate, so a growing list is native to the form rather than a failure of it.
- (decision by user) VOICE = plain language inside formal structure. The frame is institutional; the sentences are not. 'You already paid this amount three weeks ago', never 'Probable duplicate disbursement identified.' This is the accepted mitigation for direction A's austerity risk.
- (decision by user) ACCESSIBILITY FLOOR = WCAG 2.2 AA. Contrast, full keyboard operation, visible focus, screen-reader semantics on the evidence tables. Non-negotiable for a regulated surface.
- (decision by user) ORACLE ENTRY = persistent ask field on the dashboard. Typing in it opens the Oracle with the question already underway — zero navigation steps in the UJ-2 mid-meeting moment. Resolves the cost accepted when the dashboard was chosen as front door.
- (change by facilitator) PALETTE CORRECTION forced by the AA floor: brass #A47E3B on stone #E5E5E0 measures ~2.9:1, failing both the 4.5:1 text minimum and the 3:1 non-text UI minimum. Brass is redefined as #6E5426 (~5.2:1 on stone) for any text or indicator use; the original lighter tone is retained only as a fill/tint where nothing depends on perceiving it. Ink #14213D (~12.4:1) and flag #8C2F1E (~7.9:1) on stone both pass unchanged.
- (assumption by facilitator) OPEN, non-blocking: dark theme is unspecified. Direction A was rendered light-only and the product is a document-like record tool, so light-primary is the working assumption — but this is an omission, not a decision, and should be settled before UI stories are written.
